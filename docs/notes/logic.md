# Game logic: assembly back to C (agent P)

Scope: GRIMFANDANGO.EXE below 0x004bf000 except the software rasteriser (0x0040ea50-0x004710e0), the ten left-overs of
LUA.DLL and the eleven of CHORE.DLL.  IMUSE.DLL and the EXE range 0x4bf000-0x4d4100 were not touched.
The remaining functions and their reasons are listed in `docs/ASM_REMAINING_logic.md` (generated by
`tools/gen_asm_remaining_logic.py` from `names/asm_reasons_logic.json`).

| range | assembled before | assembled now |
|---|---|---|
| EXE < 0x4a0000 (without rasteriser) | 89 | 27 |
| EXE 0x4a0000-0x4bf000 | 21 | 3 |
| CHORE.DLL | 11 | 5 |
| LUA.DLL | 10 | 10 (VM core and 7 exception funclets, deliberately unchanged) |

## How the functions were converted

1. **Compiled from the Ghidra text** (`names/asm_exclude_logic.json`, 22 functions): D3D_CreateTexture, D3D_FindClosestDriver,
   D3D_SetViewportRect, Set_DrawDebugLights, Primitive_Construct, PrimitiveList_Append, Actor_CreateWalker,
   Actor_SetShadowPlane, Actor_DrawShadows, ObjectState_Create / Construct / Destruct, Sector_ClampPoint, Sector_SnapToPlane,
   Sector_FixPlaneCoordinate, SetFile_ParseSectors, Walker_TurnHeading, Walker_SetConstraint, Walker_SetSectorFrame,
   Walker_DrawDebugAxes, Text_LayoutString, Text_DrawString.  Six of them have a C++ exception frame that
   `names/seh_strip_logic.json` lets `tools/build_src.py` strip.  Prototypes that were wrong in Ghidra are corrected there
   (`names/logic_protos.json`, applied with `tools/apply_logic_protos.py`) so the callers' text passes the right arguments.
2. **Written by hand** in `build/overrides_logic.c` (EXE, about 50 functions) and `build/overrides_logic_chore.c` (CHORE.DLL:
   Cos_New{StateBased,Int,Float}Tag, CosUtil_ComponentInfo, Cos_Save, Cos_Restore).  `tools/build_src.py` finds the names
   (`load_overrides`) and puts the decompiled text of those functions under `#if 0`, `tools/gen_asm.py --select` leaves them out
   of the assembly.  A function whose signature has the return type on its own line is not found by that scan: add a
   `/* OVERRIDES: Name */` line (Collision_BoxSlide needed it; without it both the assembly and the C were linked and
   `--allow-multiple-definition` silently took the assembly).  Families: renderer set-up and tables (Build16bitTables,
   BuildMathTables, BuildProjection, ClipFace, AddMeshToCache, DrawMeshZ, AddMesh, Model3 load / radii / vertex normals,
   DrawPolygon / Point / Line, ProjectPoint, SpriteThing), maths (SinCos table, SinDeg), pixel and palette conversion,
   colour table, iris / progress bar / thumbnail renderers, Lua glue (actor chores, world to screen, control handlers,
   change primitive, print line, subtitle), actor movement and talk, walker yaw, sector shrink, shadow plane, polyglot table,
   surface creation, input axis range, collision point-in-box and box slide.

## Pitfalls found (all fixed unless stated)

* **x87 versus gcc.** `_ftol` operands are lost by Ghidra; the original keeps temporaries in extended precision.  The hand
  ports use `long double` for such temporaries, `(int)(long long)x` for `_ftol`, explicit float rounding where the original
  stores to a float, round-half-away constants (+-0.5), FRNDINT with the control words 0x52a (ceil), 0x526 (floor), 0x528
  (truncate), and `msvcrt_pow` through `__imp__pow`.  NaN compares (FCOM + `TEST AH,0x41`) differ from C's; Walker_UpdateYaw is
  written to match.
* **Casts.** A float stored through an integer slot (and the reverse) changes pictures: dark characters and grim21 showed it
  earlier; every cast-sensitive function was checked with the office shot and the original save grim21.
* **Lost call arguments** (ClipFace, DrawMeshZ, AddMeshToCache): the compiler pushes arguments before a conditional jump;
  `tools/find_lost_args.py` finds them.
* **Parameter slots reused as buffers or outputs** (Collision_BoxSlide, Polyglot_LoadTable, Surface_Create, Cos_*): locals
  replace them.  Locals Ghidra shows as separate variables but passes as one array (`&local_48` is a Vec3) must be one array
  in C: Collision_BoxSlide with separate floats gave wrong slides in 180 coll tests.
* **Return values.** A function Ghidra declares `void` can leave a value in EAX that a caller uses (CosUtil_ComponentInfo returns
  the record; the EXE reads it through Cos_InstComponentInfo).
* **Shared Ghidra project.** `tools/export_changed.py` pulls other agents' renames into the raw exports; the raw
  `functions.json` / `globals.json` / `exports.json` were restored after each export.  Changing a prototype can break compiled
  callers (Palette_FromFloatTable made Palette_ApplyGamma read a double from one dword: Palette_ApplyGamma is hand written).
* **Left assembled after a failed try:** Engine_RenderFrame (the C version crashes on a bad pointer at +0x240),
  Sector_ContainsPoint (the C comparisons with 1e-5 tolerances differ from the x87 original; the coll tier gives NaN),
  Collision_TestActorAgainstOthers (crashes at start-up), Walker_UpdateYaw as plain C (NaN compare).

## Verification (final configuration)

* Boot and Lua hook; scripted suite on a private copy: unit 180/0, walk 132/0, move 288/0, coll 470/4 (the four known failures,
  identical to the all-assembly baseline: 0 differing NAVTEST lines), misc 91/0, rules 1179/0.  The only difference to the
  baseline in `move` is the order of the `seen[...]` list, which varies from run to run (hash order of object keys).
* `build/perf/oldsaves.py --only 12,21,62`: all three saves load, tick, walk, re-save (marker round trip) and switch set.
* build/difftest oracles t2 t3 t7 t8 t9: identical to the all-assembly reference; the tour pictures: deterministic shots
  (vd tu ce ga mo sh) at 0.00-0.50 against a noise floor of 0.12-0.5; office 0.0-1.4 (reference itself varies).
* `build/difftest/logic_dt.c` (not part of the normal build) runs the original machine code (`tools/gen_asm_dual.py` renames it
  to `<name>__orig`) against the C on random inputs inside one process: Build16bitTables, BuildMathTables, Math_SinCosTable and
  Math_SinDeg (4 million trials each), Palette_FromFloatTable, Pixel_Convert, Pixel_ConvertOne, Render_BuildColorTable and
  Input_SetAxisRange: all bit-identical.  Use:
  `python -I tools/gen_asm_dual.py <asm_funcs.s of an all-assembly build> <dual.s> Name ...`, copy the test to
  `build/overrides_logic_dt.c`, `make -C build link`, run the exe with `GRIM_LOGIC_DT=<result file>` from a data directory
  (the constructor writes the result and exits), then delete `build/overrides_logic_dt.c`.
